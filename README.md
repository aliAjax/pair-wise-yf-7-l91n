# 活字排版工坊

一个纯前端本地应用，用来维护字模库、在网格版面中落字、检查字模数量是否超用、保存草稿并导出 PNG 预览图。

直接打开 `index.html` 即可使用，也可以在本目录启动静态服务访问。

## 纸样与多版保存

一张草稿可分别排三种纸样：

- 明信片（16 × 10）
- 书签（7 × 18）
- 方形小笺（12 × 12）

切换纸张只改变当前视图；每个纸样的落字位置、网格间距、横/竖排方向、翻页状态都分别保存，互不影响。

书签等格数较少的纸样若存在越界落字（例如旧数据迁移而来），越界落字不会被删除，会原样保留在原页，并在版面上方逐条列出冲突。

## 页面接续

每个纸样都可以接续多页（底部「接续新页」）。只有空页可以删除，仍带落字的页会被阻止以避免丢字。导出时按当前纸样当前页出图。

## 保存规则

保存草稿时会原地校验：

1. 作品名为空 → 提示先填写，不写入任何数据；
2. 已用过的纸样中存在空版 → 列出缺落字的纸样，不写入任何数据。

校验通过后，三种纸样（含各自方向、网格、分页与落字）一并存入草稿。

## 旧版草稿迁移

旧版只有全局 `settings + placements` 的单版数据，会在载入时自动迁移：原落字进入原纸样，另外补齐明信片、书签、方形小笺三个空版；已保存的旧草稿在「载入」时同样补齐。迁移条目会标注「旧单版已补齐纸样」。

## 脚本结构

- `papers.js` — 纸样校验：网格规格、默认版面、越界冲突检测（纯逻辑，无 DOM）
- `paging.js` — 页面接续：翻页、加页、删空页、落字统计（纯逻辑，无 DOM）
- `migrate.js` — 数据迁移：旧单版状态/草稿升级为 v2 多纸样结构（纯逻辑，无 DOM）
- `app.js` — 界面渲染、交互、本地存储与导出

纯逻辑脚本可用 Node 直接引入测试，例如：

```bash
node -e "const P=require('./papers.js'),G=require('./paging.js'),M=require('./migrate.js')"
```
